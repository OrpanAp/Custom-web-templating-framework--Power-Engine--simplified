Architecture & project structure

Learn where application code belongs and how a request moves through P.O.W.E.R. 2.0.

Know the layers

app.js                   boot + middleware pipeline
bin/power-cli.js         command-line interface
config/                  environment loader + typed settings
core/                    router, server, views, sessions, security, database
app/controllers/          request handlers
app/models/               data models
app/routes/               route definitions
app/views/                server-rendered templates
database/migrations/      schema migrations
docs/                     Markdown documentation
public/                   static assets
storage/                  local SQLite files and dev secrets
tests/                    node:test suites

The request lifecycle

  1. Security headers apply baseline browser protections.
  2. Host guard can reject unapproved hosts and enforce HTTPS.
  3. Static files are served with traversal protections.
  4. Rate limiting and body parsing constrain requests and parse JSON or URL-encoded forms.
  5. Session and user loading populate request context.
  6. CSRF checks protect unsafe same-origin requests.
  7. Router and error handling invoke your route and render failures.

MVC-style organization

ModelData access and persistence; typically extends the framework Model class.
ViewHTML templates rendered with data and shared layouts/partials.
ControllerRequest handlers that coordinate input, models, and responses.
RoutesConnect URL paths to controller methods and middleware.

The core/ layer is intended to remain independent from your app-specific code in app/. Start with routing to see the pieces working together.
