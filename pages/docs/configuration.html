Configuration & environment

Configure application settings through layered environment files, validate values, and keep production secrets out of source control.

Environment file precedence

Lower-priority sources are loaded first; the real process environment takes precedence over files.

  1. .env
  2. .env.<mode>, such as .env.production
  3. .env.local (skipped in test mode)
  4. .env.<mode>.local

Validate configuration

node bin/power-cli.js env:check
node bin/power-cli.js env:check --env=production
node bin/power-cli.js env:example
node bin/power-cli.js key:generate --write

Secret files

For container secret mounts, settings can use a _FILE variant, for example SESSION_SECRET_FILE=/run/secrets/session_secret. Never commit .env, .env.local, or files containing real credentials. Rotating the session secret invalidates existing sessions and affects encrypted two-factor secrets.

Project status: P.O.W.E.R. 2.0 is under active development. Verify integrations and follow the security and deployment guidance before production use.
