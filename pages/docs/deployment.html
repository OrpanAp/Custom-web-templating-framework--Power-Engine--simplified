Deployment

Prepare a P.O.W.E.R. app for production with safe environment settings, HTTPS, database backups, and an honest understanding of scaling limits.

Production baseline

NODE_ENV=production
SESSION_SECRET=use-a-long-random-secret
ALLOWED_HOSTS=example.com
POWER_ADMIN_EMAIL=you@example.com
POWER_ADMIN_PASSWORD=use-a-unique-password

Set secrets in your host's secret manager or protected environment, not in committed source. Validate the final configuration before starting.

node bin/power-cli.js env:check --env=production
node --disable-warning=ExperimentalWarning app.js

Production checklist

  • Use HTTPS and secure cookie settings.
  • Set a strong SESSION_SECRET and restrict ALLOWED_HOSTS.
  • Use unique administrator credentials and protect access.
  • Configure database TLS and backups; test restore procedures.
  • Run npm test and database integration tests.
  • Monitor logs, errors, resource use, and security updates.
  • Keep secrets and local database files out of Git.

Reverse proxy and live streams

When running behind your own trusted proxy, configure TRUST_PROXY=1 and the allowed hosts. Live presentation and reload streams use Server-Sent Events; proxy buffering should be disabled for those routes.

Scaling limits to plan around

Rate limiters, live presentation rooms, and development live reload are in-memory and per-process. Sessions are database-backed. Multi-process deployments need sticky routing for live/presenter paths or a shared pub/sub replacement, plus a shared rate-limiting strategy. Live reload is a development feature.

Database and uploads

SQLite can fit a single-server deployment when storage is persistent and backups are reliable. PostgreSQL or MySQL may be better for managed or multi-server deployments, but verify the integration against your server. Multipart file uploads are not currently provided by the framework.

Project status: P.O.W.E.R. 2.0 is under active development. Verify integrations and follow the security and deployment guidance before production use.
